## 操作背景

### 需求描述

完成第3次 Docker 部署后，需要将项目分享给后端同事。经过方案对比，决定使用 GitHub 作为代码分享和版本管理的平台。

### 为什么选择 GitHub？

**对比其他方案**：

| 方案 | 优点 | 缺点 | 评分 |
|------|------|------|------|
| **GitHub** | 版本控制、协作性强、跨平台 | 需要身份验证 | ⭐⭐⭐⭐⭐ |
| 阿里云服务器 | 国内快、可含 volumes | 需要服务器权限 | ⭐⭐⭐⭐ |
| Git Bundle | 离线传输、单文件 | 不支持持续协作 | ⭐⭐⭐ |
| 网盘分享 | 简单易用 | 不支持版本控制 | ⭐⭐ |
| 打包压缩 | 最简单 | 兼容性问题、无版本控制 | ⭐⭐ |

**选择理由**：
1. ✅ 标准的代码协作方式
2. ✅ 完整的版本控制
3. ✅ 在线查看代码和文档
4. ✅ 支持持续更新
5. ✅ 跨平台无兼容性问题

- URL: `https://github.com/isabellakiko/AI_Firework/security/secret-scanning/unblock-secret/...`

**重要说明**：
- 这些是测试密钥，不是生产环境密钥
- 如果是私有仓库，可以安全推送
- 公开仓库应该移除或替换密钥

## 技术要点

### 1. Git Remote 管理

**最佳实践**：
- `origin` - 个人/团队仓库（用于推送）
- `upstream` - 官方仓库（用于同步更新）

**查看所有 remote**：
```bash
git remote -v
```

**添加/删除 remote**：
```bash
git remote add <name> <url>
git remote remove <name>
git remote rename <old> <new>
```

---

### 2. GitHub CLI 身份验证

**优点**：
- ✅ 一次登录，永久有效
- ✅ 自动管理 token
- ✅ 支持 HTTPS 和 SSH
- ✅ 集成 Keychain（macOS）

**常用命令**：
```bash
gh auth login          # 登录
gh auth status         # 查看状态
gh auth logout         # 登出
gh auth refresh        # 刷新 token
```

---

### 3. GitHub Secret Scanning

**功能说明**：
- 自动扫描提交中的密钥和 token
- 支持检测：API keys, 密码, 证书, SSH keys 等
- 防止敏感信息泄露

**触发条件**：
- 推送到公开仓库
- 代码中包含已知的密钥格式

**解决方案**：
1. **允许推送**（仅测试密钥）
   - 访问 GitHub 提供的链接
   - 点击"Allow"确认

2. **移除密钥**（生产密钥）
   - 使用 `git-filter-repo` 或 `BFG Repo-Cleaner`
   - 从 Git 历史中完全移除

3. **改为私有仓库**
   - 私有仓库不会公开暴露密钥
   - 但仍应遵循最佳实践

---

### 4. .gitignore 的作用

**项目中的配置**：
```gitignore
# 依赖包（可恢复）
node_modules/
.pnpm-store/

# 构建产物（可恢复）
.next/
dist/
build/

# 运行时数据（不可恢复，不应提交）
docker/volumes/*
!docker/volumes/README.md

# 环境变量（包含密钥）
.env
.env.local
.env.*.local
```

**重要理解**：
- ✅ 被忽略的文件不会被 Git 跟踪
- ✅ 删除后无法通过 Git 恢复
- ✅ 不会被推送到远程仓库
