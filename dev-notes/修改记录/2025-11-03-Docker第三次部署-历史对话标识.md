```bash

```

```
Container docker-web-1  Recreate
Container docker-web-1  Recreated
Container docker-web-1  Starting
Container docker-web-1  Started
```

**为什么使用 `--force-recreate`？**

根据第二次部署的经验教训：
- ❌ `docker compose restart web` 不会使用新镜像
- ✅ `docker compose up -d --force-recreate web` 强制重建容器
- 容器创建时绑定的是镜像 SHA，`restart` 只重启进程，不会更新镜像

**时间消耗**：
- 停止旧容器：~2 秒
- 删除旧容器：~1 秒
- 创建新容器：~3 秒
- 启动新容器：~5 秒
- **总计**：~10-15 秒

## 技术要点

### Docker 镜像更新机制（经验积累）

**关键理解**（来自第2次部署的教训）：

1. **镜像标签 vs 镜像 SHA**
   - 标签（tag）只是一个指针，可以改变指向
   - SHA 是镜像内容的唯一标识，不可变
   - 容器绑定的是 SHA，不是标签

2. **为什么必须使用 `--force-recreate`**
   ```
   docker build 构建新镜像
         ↓
   新镜像覆盖 brand-customization 标签
         ↓
   旧容器仍然绑定到创建时的镜像 SHA
         ↓
   docker compose restart ❌ 只重启进程，不更新镜像
         ↓
   docker compose up -d --force-recreate ✅ 删除旧容器，创建新容器
   ```

3. **验证步骤的重要性**
   - 必须检查容器镜像 SHA 是否与最新镜像一致
   - 必须检查容器创建时间是否是刚刚
   - 仅靠浏览器验证不够，可能有缓存

### 本次部署改进

相比第2次部署，本次部署更加规范：

1. **提前应用经验**
   - 直接使用 `--force-recreate`，没有尝试 `restart`
   - 主动验证镜像 SHA
   - 检查容器创建时间

2. **流程更顺畅**
   - 一次性完成部署（没有重试）
   - 验证更全面
   - 文档记录更及时

## 标准 Docker 部署流程（第3版）

经过三次部署的实践，总结出最优流程：

```bash
# 第 1 步：确认 Git 提交
git status
# 确保 working tree clean

# 第 2 步：构建新镜像（5-10 分钟）
docker build -t langgenius/dify-web:brand-customization ./web

# 第 3 步：强制重新创建容器（⭐ 关键步骤，10-15秒）
cd docker
docker compose up -d --force-recreate web

# 第 4 步：验证镜像 SHA
docker inspect docker-web-1 --format='Image: {{.Image}}'
docker image inspect langgenius/dify-web:brand-customization --format='{{.Id}}'
# 两个 SHA 必须一致！

# 第 5 步：检查容器创建时间
docker inspect docker-web-1 --format='Created: {{.Created}}'
# 必须是刚刚创建的时间

# 第 6 步：检查日志
docker compose logs web --tail=20
# 确认 ✓ Ready 无错误

# 第 7 步：浏览器验证
# 访问 http://localhost:80
# 强制刷新（Cmd+Shift+R）
```

**时间消耗**：
- 构建镜像：5-10 分钟
- 重新创建容器：10-15 秒
- **总计**：~6-11 分钟

## 未来优化建议

### 1. 自动化部署脚本

创建 `deploy.sh`：
```bash
#!/bin/bash
set -e

echo "🚀 开始第 N 次部署..."

# 1. 检查 Git 状态
if [[ -n $(git status -s | grep -v "docker/volumes") ]]; then
  echo "❌ 有未提交的源代码修改，请先提交"
  exit 1
fi

# 2. 构建镜像
echo "📦 构建 Docker 镜像..."
docker build -t langgenius/dify-web:brand-customization ./web

# 3. 强制重建容器
echo "🔄 强制重新创建容器..."
cd docker
docker compose up -d --force-recreate web

# 4. 验证
echo "✅ 验证部署..."
CONTAINER_SHA=$(docker inspect docker-web-1 --format='{{.Image}}')
IMAGE_SHA=$(docker image inspect langgenius/dify-web:brand-customization --format='{{.Id}}')

if [ "$CONTAINER_SHA" = "$IMAGE_SHA" ]; then
  echo "✅ 镜像 SHA 匹配：$CONTAINER_SHA"
else
  echo "❌ 镜像 SHA 不匹配！"
  echo "容器：$CONTAINER_SHA"
  echo "镜像：$IMAGE_SHA"
  exit 1
fi

docker compose logs web --tail=5

echo "🎉 部署完成！访问 http://localhost:80"
```

### 2. 版本号管理

避免覆盖同名标签：
```bash
# 使用日期 + 序号
docker build -t langgenius/dify-web:brand-2025-11-03-v1 ./web
docker build -t langgenius/dify-web:brand-2025-11-03-v2 ./web

# 或使用语义化版本
docker build -t langgenius/dify-web:brand-v1.0.0 ./web
docker build -t langgenius/dify-web:brand-v1.1.0 ./web
```

### 3. 镜像清理策略

定期清理旧镜像：
```bash
# 查看所有镜像
docker images | grep dify-web

# 清理悬空镜像（被覆盖的旧镜像）
docker image prune -f

# 清理特定旧镜像
docker rmi <image-id>
```
