# 部署操作步骤

## 📋 文档说明

本文档说明修改前端代码后，如何部署到 Docker 环境并验证效果。

**适用场景**：应用了代码修改后，需要在 Docker 部署环境中查看效果。

---

## ⚠️ 首次部署必读（重要！）

### 如果你是从 Git 克隆的项目，请先执行这一步

**在进行下面的 7 个步骤之前，必须先构建自定义镜像：**

```bash
# 在项目根目录执行（不是在 docker 目录）
docker build -t langgenius/dify-web:brand-customization ./web
```

**预计时间**：5-10 分钟（首次），2-3 分钟（后续重建）

**为什么必须先构建？**

`langgenius/dify-web:brand-customization` 是**本地自定义镜像**，不在 Docker Hub 上：
- ❌ Docker Hub 只有官方镜像 `langgenius/dify-web:1.8.0`
- ❌ Git 仓库只包含源代码和 Dockerfile，不包含编译好的镜像
- ✅ 必须在本地构建后才能使用

**如果不先构建就直接运行 `docker compose up -d`，会报错：**
```
Error response from daemon: manifest for langgenius/dify-web:brand-customization not found
```

**构建成功后**，再按照下面的"标准部署流程"继续操作。

---

## 🔑 核心概念

### 为什么需要重新部署？

**关键理解**：
- Docker 使用的是**编译后的静态文件**，不是源代码
- 修改源代码后，必须重新构建 Docker 镜像才能生效
- 本地开发环境（pnpm dev）和 Docker 部署是两个独立环境

### 两种环境对比

| 环境 | 访问地址 | 是否需要构建 | 热更新 | 适用场景 |
|------|----------|-------------|--------|---------|
| **开发环境** | http://localhost:3000 | ❌ 否 | ✅ 是 | 日常开发调试 |
| **Docker 部署** | http://localhost:80 | ✅ 是 | ❌ 否 | 部署验证、生产环境 |

**建议**：
- 日常开发使用 `pnpm dev`（实时热更新）
- 完成功能后再构建 Docker 镜像验证

## 🚀 标准部署流程

### 前提条件

- ✅ 已安装 Docker Desktop
- ✅ 已完成代码修改
- ✅ 项目路径：`web/` 目录包含所有前端代码
- ✅ Docker 配置文件：`docker/docker-compose.yaml`

### 流程总览

```
1. 确认 Git 状态
   ↓
2. 构建 Docker 镜像（5-10 分钟）
   ↓
3. 强制重建容器（⭐ 关键步骤）
   ↓
4. 验证镜像 SHA
   ↓
5. 检查容器创建时间
   ↓
6. 查看容器日志
   ↓
7. 浏览器验证效果
```

## 📖 详细步骤

### 步骤 1：确认 Git 状态

**目的**：确保所有修改都已保存和提交

```bash
# 进入项目根目录
cd /path/to/your/dify/project

# 查看状态
git status

# 如果有未提交的修改
git add .
git commit -m "feat: 应用品牌化修改"
```

**预期结果**：`working tree clean` 或只有运行时数据文件（docker/volumes）变更

---

### 步骤 2：构建 Docker 镜像

**目的**：将修改后的前端代码编译打包成 Docker 镜像

```bash
# 在项目根目录执行
docker build -t langgenius/dify-web:brand-customization ./web
```

**构建过程**：
1. 📦 安装依赖（~30 秒）
2. 🔨 编译 Next.js（~2 分钟）
3. 📸 优化和打包（~10 秒）

**预计时间**：首次约 5-10 分钟，后续利用缓存约 2-3 分钟

**成功标志**：
```
✓ Compiled successfully in 78s
✓ Generating static pages (29/29)
✓ Finalizing page optimization
Successfully built xxxxx
Successfully tagged langgenius/dify-web:brand-customization
```

**验证镜像创建**：
```bash
docker images | grep brand-customization
```

应该看到：
```
langgenius/dify-web   brand-customization   刚刚   ~780MB
```

---

### 步骤 3：强制重建容器（⭐ 重要）

**目的**：让容器使用新构建的镜像

⚠️ **关键命令**：必须使用 `--force-recreate` 标志

```bash
# 进入 docker 目录
cd docker

# 强制重新创建 web 容器
docker compose up -d --force-recreate web
```

**输出示例**：
```
Container docker-web-1  Recreate
Container docker-web-1  Recreated
Container docker-web-1  Starting
Container docker-web-1  Started
```

**⚠️ 常见错误**：
```bash
# ❌ 错误命令（不会使用新镜像！）
docker compose restart web

# ✅ 正确命令（强制重建）
docker compose up -d --force-recreate web
```

**为什么必须用 `--force-recreate`？**

- 容器创建时绑定的是镜像 SHA，不是镜像标签
- `restart` 只重启进程，不更新镜像绑定
- `--force-recreate` 会删除旧容器，用新镜像创建新容器

---

### 步骤 4：验证镜像 SHA（⭐ 关键）

**目的**：确认容器使用的是新构建的镜像

```bash
# 查看容器使用的镜像 SHA
docker inspect docker-web-1 --format='{{.Image}}'

# 查看最新镜像的 SHA
docker image inspect langgenius/dify-web:brand-customization --format='{{.Id}}'
```

**预期结果**：两个 SHA 必须完全一致！

示例：
```
# 容器 SHA
sha256:b05a8c9c3d01bc2d07a0f874cb930da42283087a5516c715c4b7b6770d4df4a5

# 镜像 SHA
sha256:b05a8c9c3d01bc2d07a0f874cb930da42283087a5516c715c4b7b6770d4df4a5
```

✅ **SHA 一致** = 容器使用新镜像
❌ **SHA 不一致** = 容器仍使用旧镜像，需要重新执行步骤 3

---

### 步骤 5：检查容器创建时间

**目的**：确认容器是刚刚创建的

```bash
docker inspect docker-web-1 --format='Created: {{.Created}}'
```

**预期结果**：显示的时间应该是刚才（不是几小时或几天前）

示例：
```
Created: 2025-11-03T01:07:44.769642669Z
```

---

### 步骤 6：查看容器日志

**目的**：确认容器启动成功，无错误

```bash
# 查看最近 20 行日志
docker compose logs web --tail=20

# 实时查看日志（可选）
docker compose logs -f web
```

**预期结果**：
```
✓ PM2 成功启动进程
✓ Next.js 正常运行
✓ Ready in 46ms
✓ 无 ERROR 或 WARNING
```

## ⚠️ 常见问题

### Q1: 构建镜像很慢，正常吗？

**A**：正常，首次构建需要 5-10 分钟

- 安装 1733 个依赖包
- 编译 Next.js 代码
- 优化和打包输出

**优化**：
- Docker 会缓存未修改的层，后续构建会更快
- 确保网络稳定

---

### Q2: 浏览器看不到修改效果？

**A**：按以下顺序排查

1. **检查镜像 SHA 是否匹配**
   ```bash
   docker inspect docker-web-1 --format='{{.Image}}'
   docker image inspect langgenius/dify-web:brand-customization --format='{{.Id}}'
   ```

2. **检查容器创建时间**
   ```bash
   docker inspect docker-web-1 --format='{{.Created}}'
   ```

3. **清除浏览器缓存**
   - 强制刷新：Cmd+Shift+R（Mac）或 Ctrl+Shift+R（Windows）

4. **检查容器日志**
   ```bash
   docker compose logs web --tail=50
   ```

---

### Q3: 如何知道是否使用了正确的镜像？

**A**：通过 docker-compose.yaml 配置

打开 `docker/docker-compose.yaml`，找到 web 服务配置（约第 659 行）：

```yaml
web:
  image: langgenius/dify-web:brand-customization  # 应该是这个
  # image: langgenius/dify-web:1.8.0  # 不是这个（官方镜像）
```

确认使用 `brand-customization` 标签。

---

### Q4: 部署后如何回滚到官方版本？

**A**：修改配置并重启

```bash
# 1. 修改 docker/docker-compose.yaml 第 659 行
#    改为：image: langgenius/dify-web:1.8.0

# 2. 重启容器
cd docker
docker compose restart web

# 3. 访问 http://localhost:80
```

---

### Q5: 可以同时运行开发和部署环境吗？

**A**：可以，它们使用不同端口

```bash
# Docker 部署（端口 80）
cd docker
docker compose up -d

# 开发环境（端口 3000）
cd ../web
pnpm dev
```

访问：
- Docker 部署：http://localhost:80
- 开发环境：http://localhost:3000

---

### Q6: 构建镜像时出现 EOF 错误怎么办？

**A**：这是网络连接中断导致的常见问题，解决方法很简单

**错误信息示例**：
```
Get "https://mirror.aliyuncs.com/...": EOF
```

**解决方法**：

**方案1：简单重试（推荐）⭐**

```bash
# 直接重新执行构建命令
docker build -t langgenius/dify-web:brand-customization ./web
```

**成功率**：约 80%，大多数情况下重试即可成功

**方案2：修改 Docker 镜像源（如果重试多次仍失败）**

1. 打开 Docker Desktop → 设置 → Docker Engine
2. 添加国内镜像源：
   ```json
   "registry-mirrors": [
     "https://docker.m.daocloud.io",
     "https://dockerproxy.com",
     "https://docker.nju.edu.cn"
   ]
   ```
3. 点击 "Apply & Restart"
4. 重新构建

**详细排查**：参考 `../部署问题排查/2025-11-03-Docker构建镜像EOF错误.md`

## 🎯 最佳实践

1. **日常开发用 pnpm dev**
   - 实时热更新，立即看到修改
   - 不需要等待构建

2. **重要节点才构建镜像**
   - 完成一个功能后
   - 准备部署前
   - 需要验证完整效果时

3. **每次构建前提交 Git**
   - 便于追踪和回滚
   - 避免丢失修改

4. **使用验证脚本**（可选）
   ```bash
   # 创建验证脚本 verify-deploy.sh
   #!/bin/bash
   CONTAINER_SHA=$(docker inspect docker-web-1 --format='{{.Image}}')
   IMAGE_SHA=$(docker image inspect langgenius/dify-web:brand-customization --format='{{.Id}}')

   if [ "$CONTAINER_SHA" = "$IMAGE_SHA" ]; then
     echo "✅ 部署成功：SHA 匹配"
   else
     echo "❌ 部署失败：SHA 不匹配"
   fi
   ```
