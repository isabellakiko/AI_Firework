## 🎨 品牌色体系

本次定制使用以下两种品牌色：

| 颜色 | 色值 | 用途 |
|------|------|------|
| **黄色** | `#f2c823` | 行动按钮、强调文字、品牌标识 |
| **深灰** | `#615e5f` | 容器背景、专业元素 |

### 应用原则

- **黄色**：所有需要用户注意的元素（按钮、输入文字、选中状态、品牌名）
- **深灰**：所有容器背景（侧边栏、用户头像背景）
- **统一性**：相同功能的元素使用相同颜色，形成一致的视觉语言

## ⚠️ 重要注意事项

### 关键点 1：首次部署必读 ⭐ 最重要

**如果你是从 Git 克隆的项目，第一次部署时：**

❌ **不要直接运行** `docker compose up -d`
✅ **必须先构建镜像**

在项目根目录执行：

```bash
docker build -t langgenius/dify-web:brand-customization ./web
```

然后再进入 `docker` 目录启动服务：

```bash
cd docker
docker compose up -d
```

**为什么？** `langgenius/dify-web:brand-customization` 是本地自定义镜像，只存在于构建者的电脑上，Docker Hub 上不存在。

**详细步骤**：参考 `02-部署操作步骤.md`

---

### 关键点 2：品牌色必须完全一致

所有黄色元素必须使用 `#f2c823`，所有深灰元素必须使用 `#615e5f`。

不要使用相近的颜色值，这会破坏品牌一致性。

---

### 关键点 3：修改顺序建议

建议按以下顺序应用修改：

1. **侧边栏品牌化**（最复杂，7个文件）
2. **发送框品牌化**（3个文件）
3. **YOMY 品牌标识**（1个文件）
4. **用户头像品牌化**（2个文件，涉及 SVG 和 JSON）
5. **历史对话标识**（1个文件，最简单）

每完成一个模块，就提交一次 Git，这样便于追踪和回滚。

---

### 关键点 4：Docker 部署的关键命令

⚠️ **必须使用** `--force-recreate` 标志：

```bash
# ❌ 错误（不会更新镜像）
docker compose restart web

# ✅ 正确（强制重建容器）
docker compose up -d --force-recreate web
```

详见 `02-部署操作步骤.md` 的说明。

### 关键点 5：用户头像特殊说明

用户头像需要同时修改 2 个文件：
- `user.svg`（源文件）
- `User.json`（实际使用的文件）⭐ 关键

并且需要调整不透明度从 68% → 99%，否则颜色会混合。
