## 错误现象

```bash

[+] Running 0/4
```

### 触发场景

**操作流程**：
1. 从 GitHub 克隆项目到本地
2. 进入 `docker` 目录
3. 直接执行 `docker compose up -d`
4. 报错：镜像不存在

**环境**：
- 系统：Windows
- Docker Desktop：最新版
- 项目分支：`feature/brand-customization`

## 原因分析

### 根本原因

`langgenius/dify-web:brand-customization` 是**本地自定义镜像**，具有以下特点：

1. **不在 Docker Hub 上**
   - 这个镜像标签只存在于构建者的本地电脑
   - Docker Hub 上只有官方的 `langgenius/dify-web:1.8.0`

2. **Git 不包含 Docker 镜像**
   - Git 仓库只包含源代码（`web/` 目录）
   - Git 仓库只包含 Dockerfile（镜像构建配方）
   - 不包含构建好的镜像文件（镜像太大，约 780MB）

3. **docker-compose.yaml 引用了自定义镜像**
   ```yaml
   web:
     image: langgenius/dify-web:brand-customization  # 这个镜像需要本地构建
   ```

### 为什么会误以为可以直接启动？

用户可能认为：
- ❌ Git clone 后会包含所有必要文件
- ❌ `docker compose up` 会自动构建镜像

**实际情况**：
- ✅ Git 只包含源代码
- ✅ 需要**手动构建**镜像后才能启动

## 解决方案

### 方案1：构建自定义镜像（推荐）⭐

**适用场景**：需要使用品牌化版本

**步骤**：

```bash
# 1. 回到项目根目录
cd D:\dify\AI_Firework-feature-brand-customization\AI_Firework-feature-brand-customization

# 2. 构建镜像（⭐ 关键步骤）
docker build -t langgenius/dify-web:brand-customization ./web

# 3. 进入 docker 目录
cd docker

# 4. 启动服务
docker compose up -d
```

**预计时间**：
- 首次构建：5-10 分钟
- 后续重建：2-3 分钟（利用缓存）

**验证**：

```bash
# 查看镜像是否存在
docker images | findstr brand-customization

# 应该看到：
# langgenius/dify-web   brand-customization   刚刚   ~780MB

# 查看容器状态
docker compose ps

# 访问
# http://localhost:80
```

---

### 方案2：使用官方镜像（不推荐）

**适用场景**：只是想快速测试部署，不需要品牌化修改

**步骤**：

1. 修改 `docker/docker-compose.yaml` 第 659 行：
   ```yaml
   # 修改前
   image: langgenius/dify-web:brand-customization
   
   # 修改后
   ```

   ```bash

   ```

**缺点**：
- ❌ 会丢失所有品牌化修改
- ❌ 无法验证品牌化效果

## 知识点总结

### Docker 镜像的两种来源

1. **远程仓库拉取**（Pull）
   - Docker Hub、阿里云镜像仓库等
   - 使用 `docker pull` 或 `docker compose up` 自动拉取
   - 示例：`langgenius/dify-web:1.8.0`

2. **本地构建**（Build）
   - 使用 Dockerfile 从源代码构建
   - 使用 `docker build` 命令
   - 示例：`langgenius/dify-web:brand-customization`

### Git 与 Docker 的关系

- Git 管理：**源代码**（文本文件）
- Docker 管理：**镜像**（二进制文件）
- Git 不适合存储 Docker 镜像（太大，约 780MB）

### Docker Compose 的行为

```yaml
web:
  image: some-image:tag
```

Docker Compose 的查找顺序：
1. 先查找**本地镜像**
2. 如果本地没有，尝试从 **Docker Hub 拉取**
3. 如果 Docker Hub 也没有，报错
