## 💡 为什么需要前后端分离

### 原有方式的问题
1. **完整 Docker 构建慢**：每次修改前端代码需要重新构建 Docker 镜像
2. **没有热更新**：必须重启容器才能看到效果
3. **调试困难**：无法使用浏览器开发工具的完整功能
4. **迭代效率低**：简单的样式调整也需要长时间等待

### 分离后的优势
1. ✅ **即时反馈**：修改代码后 1-2 秒自动刷新
2. ✅ **完整调试**：可以使用 React DevTools、断点调试等
3. ✅ **快速迭代**：专注于前端开发，无需关心后端配置
4. ✅ **资源节省**：只重新加载前端资源，不影响后端服务

## 🔧 核心挑战

### 遇到的主要问题
1. **端口映射缺失**
   - 问题：Docker API 服务 5001 端口未暴露到主机
   - 影响：本地前端无法连接后端 API
   - 解决：修改 docker-compose.yaml 添加端口映射

2. **环境变量配置**
   - 问题：前端不知道后端 API 地址
   - 影响：API 请求失败
   - 解决：创建 web/.env.local 配置文件

3. **插件安装超时**（额外问题）
   - 问题：Ollama 插件下载超时
   - 影响：应用功能不完整
   - 解决：增加超时时间 + 使用国内 PyPI 镜像
